AI-Powered SOC Phishing Triage Agent

An AI-powered SOC workflow that analyzes suspicious URLs using threat intelligence from VirusTotal and URLScan.io, normalizes security telemetry, and generates structured phishing triage reports.

Project Overview

Security analysts investigating suspicious links often need to collect information from multiple security tools before determining whether a URL presents a potential phishing threat.

I built this project to explore how an AI SOC agent can assist with the initial analysis of suspicious URLs. The workflow uses self-hosted n8n to connect threat intelligence services, normalize the resulting telemetry, and provide the evidence to a Google Gemini-powered AI agent.

The AI agent evaluates the collected indicators, identifies key risk indicators (KRIs), determines potential targeted brands, summarizes supporting evidence, and recommends appropriate SOC investigation actions. The resulting analysis is then formatted into an HTML security report and delivered through email.

Architecture & Tech Stack

Orchestration: n8n (Self-Hosted)
Threat Intelligence: VirusTotal API v3, URLScan.io API
AI Model: Google Gemini
AI Framework: LangChain AI Agent
Notification: Gmail SMTP
Language: JavaScript / Python-compatible security concepts
Techniques: REST API integration, Base64 URL encoding, threat intelligence enrichment, telemetry normalization, LLM-based security analysis

Implementation Phases

Phase 1: Suspicious URL Input and Encoding
The workflow begins with a suspicious URL submitted by the analyst. A JavaScript code node converts the URL into the URL-safe Base64 representation required by the VirusTotal API endpoint.

Phase 2: VirusTotal Threat Intelligence
The encoded URL is sent to the VirusTotal API to retrieve available reputation and threat intelligence data. The response provides information such as vendor detections, classifications, and URL metadata that can be used as evidence during triage.

Phase 3: URLScan.io Web Analysis
VirusTotal reputation data alone does not provide the complete picture of how a suspicious website behaves. The workflow therefore submits the URL to URLScan.io for browser-based analysis.

Because the URLScan.io analysis is asynchronous, the workflow waits for the scan to complete before retrieving the resulting data. The scan can provide information such as redirects, page structure, DOM elements, infrastructure details, and screenshots.

Phase 4: Security Telemetry Normalization
The responses from the threat intelligence sources contain a large amount of raw JSON data. Before sending this information to the AI agent, I created a normalization step that extracts the security indicators most relevant to phishing analysis.

The normalized data provides the AI agent with a more consistent representation of the investigation, including the suspicious URL, VirusTotal results, potential targeted brands, DOM indicators, and other relevant findings.

Phase 5: AI SOC Agent Analysis
The normalized security telemetry is passed to a LangChain AI Agent powered by Google Gemini. The agent evaluates the available evidence using SOC-oriented phishing triage instructions.

The agent analyzes the evidence to identify key risk indicators, potential targeted brands, threat characteristics, and supporting evidence. It also generates recommended SOC actions that an analyst can review as part of the investigation.

The AI component is designed as an analyst-assistance layer rather than an autonomous decision-maker. Any classification or recommended response action should be reviewed and validated by a security analyst before being used in a production environment.

Phase 6: Automated Incident Report
After the AI agent completes its analysis, the results are formatted into a structured HTML security report. The report contains the threat assessment, supporting indicators, potential targeted brand, and recommended investigation actions.

The final report is delivered through an SMTP email workflow, providing a simple way for a SOC analyst to receive the results without manually copying the AI-generated analysis.

Example Investigation

I tested the workflow against a suspicious URL: 

https://notifyhubss.net/e236a5b10w19bb4b10e92543dc6q2d18eca6.html

VirusTotal returned multiple vendor detections and classified the URL as associated with phishing or malicious activity. URLScan.io identified Microsoft as a potential targeted brand and exposed a password-related DOM input.

The AI SOC agent used these findings as evidence and generated a structured analysis containing the threat classification, key risk indicators, supporting evidence, and recommended SOC investigation actions.

The resulting analysis was then formatted into an HTML security report and delivered to the configured SOC inbox.

Security Relevance

Phishing investigations often require analysts to combine multiple sources of evidence before determining whether a suspicious URL should be investigated further.

This project demonstrates how an AI SOC agent can sit on top of existing security telemetry and help organize that information into a structured investigation. Instead of manually reviewing raw API responses, the analyst receives a summarized analysis containing relevant indicators, supporting evidence, and suggested next steps.

The project represents a basic AI-assisted security analysis pipeline: 

Suspicious URL
     ↓
Threat Intelligence
     ↓
Telemetry Collection
     ↓
Data Normalization
     ↓
AI SOC Agent
     ↓
Threat Analysis
     ↓
Security Report
     ↓
Analyst Review

The main security concept demonstrated is not replacing the analyst, but using an AI agent to assist with repetitive first-pass analysis while keeping final investigation and response decisions under human review.
